Layers, not walls: when one fails, the next one holds

TIME: 7 minutes.

SAY: No single control is trusted alone. Picture a house: a fence and gate, locked rooms, an alarm, a key for each person, and a safe for valuables. If a burglar climbs the fence, the locked room still holds. The RSSO puts the same five layers between an attacker and the applicant database.

PREDICT (before every press): "The attacker gets past this layer. Does the next one hold?" Let the room answer, then press. Ask a non-IT participant first each time.

STORY: 1. The firewall at the edge blocks a scan for the admin page. 2. A click inside: malware on a staff PC, past the perimeter; the zones hold, so it cannot reach the database. 3. Every blocked try is logged, and the alarm reaches Ana. 4. The stolen password fails at MFA. 5. Even a stolen backup is encrypted. Each failure is caught by the next layer.

KEY POINT: the question is never "is our firewall good?" but "what holds when it fails?"

LAW: DICT Department Circular 004 (s. 2024) is titled as prescribing a layered security and defense approach for government agencies. Ask your ICT head for its text before you quote any requirement from it.

ISO/IEC 27001:2022 covers these in Annex A 8.20 networks security, 8.22 segregation of networks and 8.23 web filtering.

TIME: 4 minutes.

SAY: A firewall is a gatekeeper with a list. Four kinds, from simple to smart. A packet filter checks the address and the door number, called a port, of each piece of traffic: only HTTPS may reach the portal. A stateful firewall remembers conversations: a reply to Ben's request comes back in, a stranger's knock does not. A next-generation firewall knows the application and the user, not only the door: it can block file-sharing apps on the staff network. A web application firewall reads what is inside web requests to the portal: it blocks a login form stuffed with database commands.

PLAIN WORDS: a port is a numbered door on a computer: web pages use one, email another, remote desktop another.

Deny by default, allow by need, log what you block

Rules that work, in five steps

  1. Start from "block everything".
  2. Add specific allows: who, to what, using which service.
  3. Order matters: the firewall acts on the first rule that matches.
  4. Log what is blocked, and have someone review the logs.
  5. Filter outbound traffic too: a server that suddenly sends data to an unknown address is a warning sign.

TIME: 7 minutes.

SAY: Five rules that work. Start from block everything. Add specific allows: who, to what, using which service. Order matters, because the firewall acts on the first rule that matches. Log what is blocked, and have someone review the logs. And filter outbound traffic too.

IDS tells, IPS stops

TIME: 5 minutes.

SAY: An intrusion detection system, an IDS, watches traffic or a computer and raises an alert. An intrusion prevention system, an IPS, can also block what it finds. Network-based systems watch traffic; host-based ones watch one computer or server. Signature-based systems look for known attacks, like antivirus; anomaly-based ones look for unusual behaviour, such as a large transfer at 2:00 AM.

VOTE (first tab): "With an IDS only, what happens to the attack?" Press 1, 2 or 3 for each hand. Then reveal: it gets through, and an alert is raised. An IDS is only as good as the person who reads it.

VOTE (third tab): the 2:00 AM transfer. Then play it with and without outbound filtering.

KEY POINT: both raise false alarms, so IT tunes them, and their logs feed monitoring and, after an incident, the incident report (Module 5).

DESK SIDE: report security alerts and odd behaviour on your computer at once. You are a sensor too.

ON SCREEN: four tabs: IDS, IPS, the 2:00 AM transfer, false alarms. Steps with a question: the room votes (1 to 9 or tap), → reveals, → again plays it. A opens the summary table.

Lock, seal, sign: three tools, three jobs

What runs on this slide

Lock: AES-GCM with a fresh 256-bit key and a random 12-byte IV, from crypto.subtle. A wrong key fails GCM's authentication check, so decryption refuses instead of returning garbage.

Seal: SHA-256, a one-way fingerprint with no key. Real password storage adds a salt and a slow algorithm made for passwords (for example bcrypt or Argon2), so stolen hashes are hard to guess.

Sign: ECDSA on curve P-256 with SHA-256. The private key signs; anyone with the public key can check. Nothing on this slide leaves the computer.

TIME: 9 minutes.

SAY: Three tools, three jobs. Encryption locks data so only key holders can read it: a locked box. Hashing seals it so any change shows: a tamper seal. A digital signature proves who sent it: a signature checked against the signer's public key. And encryption without key management is false comfort.

PREDICT (before each press): "The thief has the drive. What will he see?" "One digit changes. How much of the fingerprint changes?" (All of it.) "Someone swaps the wallet number on the way. Will the provider notice?" Let two people answer each time.

CLOSE WITH: lock, seal, sign. And encryption without key management is false comfort: keep keys apart from the data, with a named custodian. That is the next slide.

KEY POINTS: Lock protects Secret; a stolen backup drive cannot be read. Seal protects Correct, and it is how the portal stores passwords: a hash, never the password itself. Sign proves who sent the payout file and that nothing changed: the e-wallet provider rejects a changed or impostor file.

PLAIN WORDS: a private key is like your own signature stamp, kept in a safe; the public key is the sample of your signature that everyone may check against.

ON SCREEN: real cryptography, computed live in this browser: each press runs the next scene (lock, thief, custodian; fingerprint, one digit, passwords; sign, verify, swapped wallet, impostor). Back goes one scene back exactly. A shows the last scene; R clears. I explains the algorithms.

Protect data while it moves, and while it is stored

TIME: 7 minutes.

RUN IT: read each card; the room calls "moving" or "stored"; place it; after Check, read each protection aloud. Nine cards, about 30 seconds each.

SAY, data moving: websites and portals use HTTPS, which uses TLS. The padlock means the connection is encrypted and the site's certificate was issued for that name by a certificate authority; it does not mean the site is honest. Current versions are TLS 1.2 or 1.3; 1.0 and 1.1 were formally deprecated in 2021. Remote work uses a VPN. File transfer uses SFTP or HTTPS, never plain FTP, which sends passwords and files unprotected. Wi-Fi uses WPA3, or WPA2-Enterprise with a personal login, with guests on their own network. Email with personal data goes encrypted, or as a secure link with access control: NPC Circular 2023-06 requires secure transmission for emails that carry personal data.

SAY, data stored: laptops and phones have full-disk encryption, so a lost device does not mean lost data. Databases and files use database or file-level encryption for sensitive personal information. Removable media: office-issued encrypted USB drives only. Backups: encrypted, with at least one copy offline.

WATCH FOR: the nightly backup. Some will say "moving". It moves once a night but sits on a drive all day: stored is the risk.

ON SCREEN: click a card, then Moving or Stored; Check shows the protection for each; A places all.

Moving, stored, keys: is this key safe?

TIME: 6 minutes.

SAY: encryption is only as good as the care of its keys. The RSSO decides four things. Who holds the key? A named key custodian, for example Ana, with a backup custodian. Where is it kept? Apart from the data it protects, never on the same drive or server. Who can recover it? Through a sealed recovery procedure approved by the head of office. When does it change? On a schedule, and at once when a custodian leaves or a key may be exposed.

VOTE: five cases. Hands up for "safe" (press 1 per hand) and "not safe" (press 2), then reveal.

ANSWERS: 1. Not safe: whoever steals both can read everything. 2. Safe. 3. Not safe: change it at once when a custodian leaves. 4. Not safe: send the password another way, or better, use the provider's business portal. 5. Not safe: one absence locks the office out of its own data.

MEMORY PHRASE: moving, stored, keys. Protect data while it moves, while it is stored, and protect the keys.

ON SCREEN: press 1 or 2 for each vote; → reveals the answer with the guide's key rule; → next case.

Zero Trust is a strategy, not a product you buy. First steps: list people, accounts and devices; MFA first for email, VPN and admin accounts; zones; logs you look at; access reviewed on a schedule.

TIME: 3 minutes.

SAY: never trust, always verify. Being inside the office network proves nothing. Every request to reach data is checked: who you are, from which device, and whether your role needs it. Four habits: verify every request; assume breach; least privilege; keep checking. Zero Trust is a strategy, not a product you buy. NIST Special Publication 800-207 sets out its principles: every resource is protected, all communication is secured whatever the network location, and access is decided for each request by policy.

Why a security key resists phishing

TIME: 6 minutes.

SAY: a code by SMS or voice call is better than a password alone, but codes can be stolen through SIM swaps and fake login pages. A code in an authenticator app, or a push with number matching, is stronger: number matching blunts MFA fatigue, but CISA calls it an interim step. A security key or passkey, FIDO2, is strongest: it resists phishing, because the key checks the real site's address. CISA strongly urges phishing-resistant MFA, based on FIDO/WebAuthn or PKI, since 31 October 2022.

  • Never reuse an office password anywhere else

Checking a password without sending it

Access goes to roles that match jobs; people are given roles

Least privilege

Each role gets only what the job needs.

Two hands on money

No one person can both create and approve a payout, or change an e-wallet number and release the payment.

Joiner, mover, leaver
